# Changelog

版本号规则与修改流程见 `references/self-iteration.md`：任何版本变更必须有 ledger 证据 + `python evals/run_evals.py` 门禁通过 + 人工确认。

## 1.6.0 — 2026-09-15

来自用户反馈「**新增一个子文件 md，作为这篇论文的专业术语，不然老是看中文失去了英文的能力，也是需要全量输出的**」（触发条件 1：用户明确要求迭代；依据 ledger 第 14 条）。缺口：单篇笔记只有中文讲解与公式符号表——读者读完认得住概念却记不住英文原词，检索、写作用英文表达时会退化；"术语速查"此前只存在于合集层（每条一句话、跨论文），缺单篇、全量、中英对照的形态。

- **新增模式 H「专业术语表」**：产物 `术语-<短名>.md`，六节固定骨架（一、怎么用这份表 / 二、核心术语 / 三、分领域术语 / 四、易混对照 / 五、英文原句摘录 / 六、缩略语索引）+ 六列表头（英文术语｜缩写｜中文译名｜一句话解释｜在本文中的角色｜出处），模板 `references/terms-template.md`（含"全量"扫描法与 11 个检查码表）
- **默认交付集再扩一件**：说"读论文 / 讲论文 / 总结 / 精读"时默认产出 **A + B + C + E + F + H 六件**（G 照旧必做）。`SKILL.md` 选择规则、Step 4 成文要求、Step 6 交付纪律 1 与 3、`quality-rubric.md` 第 21 条、`README.md` 同步改写；模式表由七种扩为八种
- **校验器新增 `terms` 模式与 11 个检查码**（7 ERROR + 4 WARN）：`E-TERM-SEC` / `H1` / `TABLE` / `EN` / `CITE` / `EMPTY` / `DUP`，`W-TERM-MIN` / `QUOTE` / `ABBR` / `SORT`。其中 `E-TERM-EN` 是本模式存在的技术理由——**英文列只写中文译名会被直接拦下**；`TERMS_CITE_RE` 从实现第一天就同时接受裸标记与 `[原文 p.7]` / `[原文 p.7-8]` 带页码形式（吸取 `FAQ_CITE_RE` 那类"模板说合法、校验器不认"的口径不一致教训，见 ledger 第 12 条）
- **门禁新增用例 7「专业术语表」**：12 个 fixture（good 1 + warn 4 + bad 7）+ **61 条断言**，断言总数 **298 → 359**；`--mode auto` 对全部 12 个 fixture 与 `--mode terms` 输出逐字相同；7 项变异测试全部让门禁变红（删掉 `TERMS_CITE_RE` 页码分支一项就使 26 条断言失败、连 good fixture 都变红，证明该守卫有牙）
- **rubric 新增 I 节 8 条人工项（39–46）**：英文列必须是论文里的原始写法、"一句话解释"不许同义反复、"全量"靠抽样 10 条核对、`[原文 p.N]` 真伪只能人查、第五节必须是原文摘录而非自写英文——机器查不了的都留在人这一侧
- **`references/self-iteration.md` 的 `mode` 枚举补 `index` 与 `terms`**：`index` 是 1.4.0 引入模式 G 时漏补的（属 1.3.1 修过的同一类枚举漂移），`terms` 为本轮新增
- **`feedback/ledger.example.jsonl` 补一条 terms 示例**
- **已知边界（如实记录，本轮未修）**：
  1. `W-TERM-QUOTE` 要求的"≥5 条英文原句"对**材料只到摘要/代码**的论文语义偏松——真实案例 `paper-notes/MFAA/术语-MFAA.md` 用论文标题、期刊名与 6 条官方代码语句凑到 8 条通过；若严格要求"论文正文原句"，这类论文必然告警。是否按材料层级分档，留待下一轮由 ledger 决定
  2. "全量"没有机械证明：`W-TERM-MIN`（二、三两节 < 15 行告警）只是下限代理指标，完整性靠 rubric 第 42 条的抽样人工核对
  3. `E-TERM-TABLE` 只测了"数据行列数 ≠ 6"这条臂；"表头列数不对"没有独立 fixture——改坏表头会连带触发 `W-TERM-MIN` / `W-TERM-ABBR`，无法满足"除目标缺陷外其余合规"
  4. 模式识别只看文件名词干 `术语`：内容是术语表但文件名不含"术语"的笔记，`--mode auto` 会回落 deep（与其余各模式同一设计，非本模式特有）

## 1.4.0 — 2026-09-14

来自用户要求「**paper 生产的也由 wiki 管理**」：单篇笔记之外要有**合集层**，而且这一层本身要能被机械校验（依据 ledger 第 7 条）。

- **新增模式 G「笔记库索引」**：产物 `paper-notes/README.md`，一个库一份、随论文累积而**生长**。固定五节——主题清单（按 `### <主题>` 分组的条目）/ 术语速查 / 跨论文对比 / 未解决问题 / 证据强度总览；条目形状 `- [<短名>](./<短名>/README.md) — 一句话结论（证据：<类型>；代码：<有|无>）`，模板见 `references/index-template.md`
- **增量续写规则**：只追加、不重排；术语表只增不删；同一指标数字冲突时两列并列（禁止取平均/只留一个/沉默）；改旧结论必须留痕 `（更新：YYYY-MM-DD，原因）`；`最近更新` 与收录篇数同步
- **新增校验模式 `index` + 10 个检查码**：`E-IDX-`×7（标记 / H1 / 五节齐序 / 链接可达 / 条目形状 / 重复登记 / 证据类型合法）与 `W-IDX-`×3（漏登记反向检查 / 术语表三列 / 最近更新行）
- **门禁新增「用例 6 · 论文库索引」**：断言 **256 → 298**（+42），其中 bad fixture 用「ERROR 码集合恰为该码」锁定，避免被同目录其它 fixture 的 WARN 干扰
- **新增 fixture** `evals/index-cases/`：12 个索引 fixture + 9 个被链接目标（good / warn / bad / orphan / linked），`orphan` 与 `linked` 成对存在以证明「漏登记」告警不是恒真
- **真实产出接线**：`paper-notes/README.md`（MFAA 笔记库索引）= 本模式的第一个真实产出，实测 `--mode index` 10 项检查全过
- **没有新增不可妥协规则**：索引的诚实性要求已被规则 1（冲突必须并列）与规则 3（不编造）覆盖，非妥协规则仍为 10 条（防膨胀上限 ≤10）
- **测试强度自证**：两次独立变异测试共 **8 项**（子代理 3 项 + 复核者 5 项，含它没测的更新行正则与标记常量）——每项都让门禁变红，恢复后校验器哈希逐字节一致、门禁复绿

**已知边界（有意留白，不是 bug）**：

- `--mode auto` 只认首行标记：标记写错或丢失时不会判为索引，会退回深读模式报一堆 `E-DEEP-*`。**校验索引请用显式 `--mode index`**（模板与 README 已写明）
- 条目的链接**文本**不做约束（允许写成论文全名的装饰形式），只约束目标路径必须与磁盘目录名一致且真实可达。原先把「链接文本必须等于目录名」写成硬约束属过度承诺，已改为文档如实描述，而不是加一条会误伤的检查
- 代码已实现但**尚无断言**覆盖的分支：`E-IDX-ENTRY` 的「链接目标形状」分支、`E-IDX-SEC` 的五节乱序分支、`E-IDX-H1` 的多 H1 分支、`W-IDX-TERM` 的无表/仅表头分支、深层嵌套与隐藏目录的孤儿行为
