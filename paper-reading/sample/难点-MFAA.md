# Enhancing the Transferability of Adversarial Attacks via Multi-Feature Attention · 难点与解答

## 一、为什么要跨层递归聚合重要度，直接把多层梯度加起来不行吗

- **难点**：把多层梯度直接相加，和论文的"递归"聚合，实际差别在哪
- **为什么难**：前提是先理解"不同层的特征尺度不同"，而论文正文没有专门说明尺度对齐这一步
- **常见误解**：❌ 以为递归只是写法上的嵌套 → ✅ 递归的关键是每一步都先做 L2 归一化，把各层贡献压到同一量级
- **解答**：各层特征的数值尺度差异很大（浅层通道多、响应幅值大），直接相加会让某一层主导引导图。论文的聚合是自深层向浅层逐层传递，每一步先归一化再叠加，使每层贡献量级可比，最终引导图同时带有深层的语义信息和浅层的细节信息 [摘要]；官方实现里对应 L2 归一化后的递归相加，权重再取负归一化 [代码]。因此"递归"不是写法偏好，而是为了让跨层聚合在数值上成立 [推断]。
- **自检**：如果把递归中的归一化去掉，引导图会更偏向浅层还是深层？

## 二、LAG 的重要度估计和 FIA 差在哪

- **难点**：两个方法都在"梯度乘特征"这条线上，公式外形很像，差别容易被忽略
- **为什么难**：需要先知道 FIA 的重要度是在单层特征图上算的，才能看出本文改了什么
- **常见误解**：❌ 以为本文只是换了个损失函数 → ✅ 真正的差别在重要度的取值范围从单层扩到跨层
- **解答**：FIA 用单层特征图的梯度加权得到重要度，只覆盖一个特征尺度；LAG 把重要度扩展到多层并递归聚合，再叠加随机掩码平均 [摘要]。在 VGG-16 源模型攻击 12 个目标模型的对比里，本文报 98.4％、FIA 报 92.8％ [二手]；这组数字来自二手转述，未在官方摘要中出现，按待核对处理。
- **自检**：本文相对 FIA 的两处改动，分别落在重要度估计的哪个环节？

## 三、为什么要把模型权重取负，削弱正确类特征是什么意思

- **难点**：公式里的负号决定了"攻击什么"，但它看起来只是归一化的一部分
- **为什么难**：需要把"特征支持正确类别的强度"和"对抗样本要降低正确类置信度"这两件事连起来
- **常见误解**：❌ 以为取负是数值稳定手段 → ✅ 取负是攻击方向的语义：主动削弱支撑正确分类的特征
- **解答**：EA 项度量的是特征与正确类别之间的正相关强度，取负之后作为扰动方向，等于削弱那些支撑正确类的特征，这与对抗攻击降低正确类置信度的目标一致 [摘要]，官方实现里权重确实是取负后再归一化 [代码]。这里还有一处落差需要知道：官方代码最终优化的损失取的是指定层的交叉熵项（代码里为 `lossx2`，绑定层 `block2/unit_7`），注意力项被计算但没有直接进入最终损失，而论文把多特征注意力摆在整个方法的核心位置 [代码][推断]。
- **自检**：如果只保留交叉熵项、把注意力项去掉，论文的消融是否直接回答了成功率的下降幅度？

## 四、论文写的是乘范数，代码里是归一化后相加，复现该按哪个

- **难点**：同一处聚合，论文公式与官方实现的行为不一致，且两者数值效果差别很大
- **为什么难**：一个是在放大尺度，一个是在统一尺度，照抄公式会得到完全不同的引导图
- **常见误解**：❌ 直接照论文公式复现，然后认为"论文不可复现" → ✅ 以官方代码为准，并把差异写进实验说明
- **解答**：以官方仓库为准：聚合实现为 L2 归一化后的递归相加，权重取负后再做 L2 归一化 [代码]。默认值也有文档与代码不一致的地方，官方代码默认保留概率 `probb=0.8`，而仓库 README 的示例给的是 0.7 [代码]。这类差异说明论文公式更接近概念示意，凡是要做复现或横向对比，都应当在实验设置里注明"按代码实现"，而不是把公式差异当成对方结果的解释 [推断]。
- **自检**：如果严格按论文公式实现，你会预期攻击成功率偏高还是偏低，为什么？

## 五、88.5％、94.1％、89.6％、95.1％ 这一堆数字该怎么读

- **难点**：同一篇论文出现多组攻击成功率，数值相近却对应不同设定
- **为什么难**：不看设定就无法判断哪两个数字可以比较
- **常见误解**：❌ 把不同来源、不同设定的数字放在一起比较或取平均 → ✅ 每个数字都必须带设定，冲突就并列
- **解答**：官方摘要给出两组：单模型攻击下带防御黑盒模型的平均攻击成功率由 88.5％ 提升到 94.1％，集成攻击下由 86.6％ 提升到 95.1％ [摘要]。二手转述给出的"89.6％ 提升到 95.1％"与官方摘要的 86.6％ 起点冲突，另有 VGG-16 源模型 98.4％、9 种高级防御下由 56.7％ 提升到 62.8％ 等摘要中未出现的数字 [二手]。处理方式：以官方摘要为基线，二手数字标"待核对"并保留冲突，不做平均也不静默取一个 [推断]。
- **自检**：94.1％ 与 95.1％ 各自对应的攻击设定是什么？

## 六、为什么中间层的攻击效果反而最好

- **难点**：直觉上深层特征更"高级"，攻击深层似乎应该更有效，但实验结论相反
- **为什么难**：需要理解"源模型特异性"与"跨模型共性"之间的权衡
- **常见误解**：❌ 认为层越深攻击越强 → ✅ 深层特征与源模型绑定更紧，中间层兼顾判别力与共性
- **解答**：层选择实验显示中层优于最深层，二手转述称在 VGG-16 上以 Conv3_3 效果最好 [二手]；一种解释是深层特征的源模型特异性更强、可迁移的共性更少，而中间层既保留足够判别信息又更容易迁移 [推断]。官方代码把最终损失的绑定层设为较浅的 `block2/unit_7`，与该方向一致 [代码]。论文是否给出了因果层面的验证，手上材料未覆盖，按未核实处理。
- **自检**：换成 ResNet 源模型时，按这套逻辑中间层大致会落在哪个 block？

## 七、随机像素消除为什么要跑 30 个掩码，这不就是数据增强吗

- **难点**：随机掩码看起来像数据增强，容易低估它在重要度估计里的作用
- **为什么难**：要区分"改变训练样本分布"和"降低估计方差"这两件事
- **常见误解**：❌ 以为掩码是在扩充训练数据 → ✅ 掩码是在做重要度的方差削减
- **解答**：单次随机掩码下，哪些像素被保留是随机的，得到的重要度带有很大随机性；对多个掩码图像的重要度求平均可以压低这部分方差，得到更稳定的估计，官方代码默认掩码数为 30、保留概率 0.8 [代码]，论文的机制描述与之一致 [摘要]。这与数据增强不同：数据增强改变的是训练样本分布，掩码改变的是重要度估计的稳定性，攻击本身仍只在原图上迭代 [推断]。
- **自检**：把掩码数量从 30 降到 3，最先变差的是攻击稳定性还是攻击强度？

## 八、动量项为什么要除以 L1 范数，直接取符号不行吗

- **难点**：分母取 L1 还是 L2、或者干脆用 sign，看起来只是实现细节
- **为什么难**：这一步直接决定每步扰动的幅度分布，但论文只用"动量"一笔带过
- **常见误解**：❌ 以为除以 L1 范数等价于 sign → ✅ 它保留了不同像素之间的相对权重
- **解答**：除以梯度绝对值和（L1 范数）在保留方向的同时抑制幅度爆炸，相比 `sign()` 保留了像素间的相对大小，这一写法与 MI-FGSM 的形式一致，本文沿用 [代码][推断]。官方默认值为动量系数 `mu=1.0`、步长 `alpha=1.6`、迭代 10 次、无穷范数半径 `max_epsilon=16`，更新式在代码里写为 `adv + alpha * sign(noise)`（加号）[代码]。注意论文表述与代码在更新式符号上存在转录差异，复现时以代码为准 [推断]。
- **自检**：把 L1 归一化换成 L2 归一化，扰动分布会变得更稀疏还是更稠密？
