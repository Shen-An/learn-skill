# 人工质检清单（机器查不了的项）

机械项（结构、公式定界符与独占行、表格列数、引用范围、来源类型声明、模式混装、笔记库索引结构）由 `scripts/check_paper_note.py` 覆盖；本清单只留机器判不了的人工项。逐条打勾，任一不过就返工。

## A 忠实性（最高优先）

1. 每个事实断言都能归到 `[原文 p.N]`/`[代码]`/`[摘要]`/`[二手]`/`[OCR]`/`[推断]` 之一；没有"来路不明"的陈述。
2. 低置信来源没有单独支撑核心结论；`[二手]` 数字均标了待核对或已核对结果。
3. 论文没说的动机、没做的实验、没有的数字，都写成"未提及"，没有被领域常识补写成论文主张。
4. 冲突数字并列呈现，没有取平均或选择性沉默。
5. PDF 来源的引用带页码锚点；OCR 来源标注了识别风险。

## B 论证链完整度

6. 能读出"已有方法为什么不够 → 本文机制为什么够"的因果推进，而不是并列介绍模块。
7. 本文机制明确了：替换了哪个组件、多付了什么代价（超参/算力/假设）。
8. 与最接近的 1–2 个方法有逐点差异对比，不是"性能更好"这种结论式比较。
9. 每个关键数字都带设定（源模型、目标模型、基线、指标口径）。

## C 讲解密度（面向"有通用基础、无小方向基础"的读者）

10. 小方向术语首现都有大白话解释 + 与相邻概念的分界。
11. 公式都配了"直觉上等价于什么"的一句话，不是只给符号定义。
12. 递归/迭代机制说明了起点、方向、终止条件中至少两项。
13. 没有为了显得详细而铺陈的背景常识（读者已有领域基础）。

## D 边界与诚实

14. "局限性与未来工作"分列论文自述与你的独立判断，两者没有混写。
15. 独立判断给出了理由（依据哪条证据或哪个评测缺口）。
16. 证据与出处节列出了全部"未核实/未提及"项与可核查入口（页码、图表号、源码文件、DOI）。
17. 没有把评测范围的不足（如只测了分类模型）说成方法本身的局限，也没有反过来。

## E 交付语气与呈现

18. 无寒暄、无自述、无"如需进一步"式结尾。
19. 结尾"一句话总结"是把全篇压成一句可复述的话，不是章节标题的重复。
20. **模式分离**：讲解文档里没有思维导图或填表；导图与表格各自独立成文件、独立成块呈现，读者不必在一篇长文末尾再读一遍同样的内容。
21. **默认集成套且开头有清单**：说"读论文/讲论文/总结/精读"时 A+B+C+E+F+H 六件全部落盘（G 照旧必做）；交付开头先给"文件清单 + 每件一句话"，并写明本次省略了默认集里的哪一件及原因——**缺件又没声明原因 = 不通过**；随后再分块呈现。

## F 格式可渲染（人工肉眼确认一次）

22. 公式在至少一个渲染器（Obsidian / GitHub / VS Code 预览）里显示为数学，而不是裸露的 `\Delta_i` 源码。
23. 行间公式是 `$$` 独占一行的块，没有 `$$ ... $$` 与公式同行的写法。
24. 使用 `\lVert ... \rVert` 而非 `\|` 表示范数，避免表格解析错列。
25. 符号表能独立读懂：每个符号有含义，跨节含义不同时分别列出。

## G 可渲染导图与难点文档

26. `导图-<短名>.md` 是**恰好一个** ` ```mermaid ` mindmap 块：根节点唯一、四个固定分支顺序正确、层级 ≤ 4。
27. 节点文本里没有 ASCII 的 `( ) [ ] { } , ; : %`（会让 Mermaid 解析失败）；需要标点就用中文标点。
28. 交付前在 Obsidian 或 GitHub 里肉眼确认过一次渲染结果；如果读者的渲染器是 DSH Web GUI，要明确告知它只做语法高亮、不出图，看导图请打开 `导图-<短名>.md`（Obsidian / GitHub）。
29. `难点-<短名>.md` 的每条难点都**来自材料**（原文/代码/摘要/二手），不是凭空推测"读者大概会问什么"。
30. 每条 `**解答**` 都带来源标记；`**常见误解**` 只写真实容易发生的错法，没把握就留空（缺字段只是 WARN，编造误解更糟）。
31. 难点文档与讲解文档不重复搬运：难点讲"卡在哪 + 怎么破"，机制细节指向 `深读-<短名>.md` 的对应小节。

## H 笔记库索引（合集层，`paper-notes/README.md`）

32. 条目结论与对应笔记**同源同强度**：摘要层得出的数字没有被写成"论文证明"，二手数字带着"待核对"。
33. 磁盘上每篇笔记都被登记过（`W-IDX-ORPHAN` 只兜得住子目录形式；文件级漏登要人工对着目录看一眼）。
34. 跨论文对比里同一维度的冲突数字**两列并列**并标"待核对"，没有取平均、没有只留一个、没有沉默。
35. 术语速查能当"入口"用：只收最早出现的那篇，解释写"与相邻概念差在哪"，不是术语的完整定义。
36. "未解决问题"区分**论文自述**与**你的疑问**；材料不够时写"待获取全文后补"，而不是替论文编造局限。
37. 增量续写留痕：改过的旧结论带 `（更新：YYYY-MM-DD，原因）`；`最近更新` 日期与收录篇数同步更新。
38. 索引不复制正文：读它能决定"下一步点开哪篇"，而不是在索引里重述方法细节。

## I 专业术语表（`术语-<短名>.md`，模式 H）

39. 英文列是**论文里的原始写法**（首字母大小写照抄），不是自己造的英文，也不是中文译名的回译。
40. "一句话解释"讲的是"它是什么 + 与相邻概念差在哪"，不是同义反复（"迁移性就是能迁移的性质"这类循环定义不算解释）。
41. "在本文中的角色"写本文拿它做什么、替换了什么、下了什么结论；写"很重要""核心概念"这类空话算不过。
42. **全量**：随机抽 10 个正文里出现过的术语，逐个都能在表内找到；材料只到摘要时不得按"全文口径"收词，要在开头写明覆盖到哪一层。
43. 出处真实性：抽查 3 条 `[原文 p.N]`，翻到那一页确实指得到；只有摘要的条目**不许**写成 `[原文 p.N]`（格式查得出，真伪只能人查）。
44. 第五节英文原句是**原文摘录**，不是自己改写的英文充当原文；中文直译不添加原文没有的因果与评价。
45. 不越界：机制细节指向 `深读-<短名>.md`，公式符号归深读的符号表，术语表只解决"这个词英文叫什么、它在这篇里干什么"。
46. 易混对照成对或成组，每行写"差在哪"，并覆盖本文里最容易混的那几组（如迁移性 vs 鲁棒性、白盒 vs 黑盒、有目标 vs 无目标攻击）。
