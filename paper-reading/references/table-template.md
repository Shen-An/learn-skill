# 模式 B 模板：逐篇填表（`表格-<短名>.md`）

## 硬结构（机械校验会查）

文件**只能有一张表**，表格之外不得有任何非空行（不写标题、不写说明、不写结语）。

```markdown
| 维度 | 内容 |
|------|------|
| 论文标题 | |
| 作者 | |
| 发表年份 | |
| 研究问题 | |
| 研究方法 | |
| 主要发现 | |
| 创新点 | |
| 局限性 | |
| 与本研究的关联 | |
```

- 表头必须严格是 `| 维度 | 内容 |`；9 个维度**齐全且顺序一致**。
- 每行必须以 `|` 开头、以 `|` 结尾。
- 每个"内容"格要么有实质内容，要么写"未提及"；不得留空。

## 填写纪律

- 每格 **1–3 句**，超过 3 句会被机械校验拦下。宁可精确，不要铺陈。
- 表格里放不下解释，就不要解释：细节留给 `深读-<短名>.md`。
- 论文未涉及该维度 → 填 `未提及`；**不要**用领域常识代填。

## 交付纪律（必须与讲解文档分开）

- 表格**独立成文件**（`表格-<短名>.md`）、**独立呈现**：不要把它塞进 `深读-<短名>.md`，也不要贴在一段讲解之后当附录。
- 同一条回复若要交付多件，表格单独成块，块首写明文件名。
- 数字必须带设定（"VGG-16 为源、12 个目标模型平均 98.4%"），不写孤立百分比。
- 二手来源的数字在格内标注，如 `98.4%（[二手]，与官方摘要的 88.5%→94.1% 口径不同，待核对）`。
- `与本研究的关联`：只在用户提供了自己的研究背景时才写实质内容；否则填 `未提及`（不要臆测用户的研究方向）。
- `发表年份`：写论文正式发表的年份；预印本与正式版年份不同时写成 `2025（正式）/ 2024（预印本）`。
- `作者`：3 人以内写全名，超过 3 人写 `第一作者 et al.（共 N 人）`。
- 只输出表格：交付时不要在前面加"以下是填好的表格"之类的话。
