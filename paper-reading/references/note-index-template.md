# 单篇索引模板（`paper-notes/<短名>/README.md`，模式 note）

用途：一篇论文的笔记目录里会散落六到八份文件（深读、表格、思维导图、导图、难点、术语，有时还有综述片段与 `_source/` 原文导入产物）。**单篇索引**是这个目录的入口：读者先看它，就知道这篇论文值不值得读、每份文件是干什么的、哪些结论可信、还有什么没核。

它与合集层索引（`paper-notes/README.md`，模式 G）分工不同：模式 G 管**跨论文**（主题清单、术语速查、跨论文对比），模式 note 管**单篇内部**（文件清单 + 证据强度 + 待核入口）。

> **为什么现在才有机械校验**：这一层此前的短板不是"写得不好"，而是"没人查"——真实案例是 `paper-notes/MFAA/README.md` 的文件清单漏登记了两个早已交付的产出（导图、难点），后来又差点漏第三个（术语）。清单不全的索引比没有索引更误导人，所以从 v1.7.0 起它是可校验的。

## 一、骨架（逐字照抄结构，内容按论文替换）

```markdown
<!-- paper-reading: note-index -->

# <短名> 论文笔记索引

论文：<完整标题>（<venue 年份>，DOI <doi>，作者 <第一作者 等>）

一句话结论：<80 字以上；把"做了什么改动 + 换来什么 + 代价/前提是什么"写进一句话>

**交付约定（skill vX.Y.Z）**：<本次交付了哪几件、哪件是回补的、有哪些特殊约定>

## 文件

- [深读-<短名>.md](./深读-<短名>.md)：精读讲解（模式 A）——<一段话说明覆盖了什么>
- [表格-<短名>.md](./表格-<短名>.md)：逐篇填表（模式 B）
- [思维导图-<短名>.md](./思维导图-<短名>.md)：四分支思维导图（模式 C，文本大纲）
- [导图-<短名>.md](./导图-<短名>.md)：同一导图的 Mermaid 可渲染形态（模式 E）
- [难点-<短名>.md](./难点-<短名>.md)：难点与解答（模式 F）
- [术语-<短名>.md](./术语-<短名>.md)：中英对照全量术语表（模式 H）
- [_source/<原名>.md](./_source/<原名>.md)：PDF 导入产物（带 `<!-- page:N -->` 页锚点）   ← 只有附件时才写

## 证据强度提示

- 高置信（原文/代码可核）：<逐条列出>
- 低置信（我的推断或二手转述）：<逐条列出>
- 未核实（本版本无法核）：<逐条列出>
- 已标冲突（待核对）：<逐条列出，写清冲突双方的口径差异>

## 待核入口

- 正文：DOI <doi>（<怎么拿到>）
- 代码：<仓库与关键文件>
- 对照工作 / 附录：<缺失部分与补法>
```

**第一条标记行不能删**：它是 `--mode auto` 认出"这是单篇索引"的唯一依据（文件名都是 `README.md`，靠名字区分不了模式 note 与模式 G）。缺了它，`--mode auto` 会把文件当深读讲解去查，报出一串 `E-DEEP-*`。

## 二、六条硬要求（校验器会拦）

| 要求 | 违反时的码 |
|---|---|
| 首个非空行是 `<!-- paper-reading: note-index -->` | `E-NOTE-MARKER` |
| 之后是唯一的 H1 且以「论文笔记索引」结尾 | `E-NOTE-H1` |
| 第一个 `##` 之前有 `论文：` 与 `一句话结论：` 两段 | `E-NOTE-META` |
| `一句话结论：` 正文 ≥80 字（中文按字、英文按词） | `W-NOTE-CONCL` |
| 有 `## 文件` 与 `## 证据强度提示` 两个小节 | `E-NOTE-SEC` |
| 有 `## 待核入口` 小节 | `W-NOTE-ENTRY` |
| `## 证据强度提示` 里至少一条列表项 | `E-NOTE-EVID` |
| 全文相对路径链接都能解析到真实文件 | `E-NOTE-LINK` |
| 目录里每个 `<模式前缀>-*.md` 都被登记进 `## 文件` | `E-NOTE-COVER` |
| 每条交付物登记都带 `（模式 X）` 标签 | `E-NOTE-KIND` |
| 有 `_source/` 就至少登记一条 | `W-NOTE-SRC` |

交付物前缀白名单（只扫同目录一层，不递归）：`深读` / `表格` / `思维导图` / `导图` / `难点` / `术语` / `综述`。别的前缀（例如自设的 `实验记录-`）不参与完整性检查，登记不登记都不会报错——但**登记了也仍然是链接校验的对象**。

## 三、`## 文件` 怎么写才不出错

1. **文件名逐字对应**：链接目标就是目录里的真实文件名（含 `-<短名>` 后缀）。改名后忘了同步索引 → `E-NOTE-LINK`。
2. **一条交付物一行**，行首 `- [文件名](./文件名)：`，说明里**必须**含 `（模式 X）`。
3. **漏登记比漏写链接严重**：`E-NOTE-COVER` 会点名"目录里有但清单里没有"的文件。新增一件产出时先补索引，再交付。
4. `_source/` 里通常有多份文件（原件 PDF 副本 + 抽取出的 Markdown），**登记抽取产物那一条即可**，不必逐个列 PDF。
5. 索引本身（`README.md`）不用登记自己。

## 四、`## 证据强度提示` 怎么写

按四类分（缺类不报错，但四类混成一坨会失去它的用处）：

- **高置信（原文/代码可核）**：带页码或代码位置的具体条目，例：`论文身份与 DOI [原文 p.1]`；
- **低置信（我的推断或二手转述）**：写清"这是谁的推断"，例：`通信量百分比换算（我的换算，非论文主张）`；
- **未核实（本版本无法核）**：写清缺什么才能核，例：`Theorem 1 的证明（附录不在本版本 PDF 内）`；
- **已标冲突（待核对）**：两个来源的数字都写出来并说明口径差异（纪律见 `grounding-rules.md`）。

这一节是给"想引用这篇笔记的人"看的：他必须在读之前就知道哪句话能直接引、哪句话得回去核。

## 五、常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 删掉或改动标记行 | `--mode auto` 判成深读，报一串 `E-DEEP-*` | 标记行永远放第一行，逐字照抄 |
| 文件清单只写"本次新增的" | `E-NOTE-COVER`：老产出成了隐形文件 | 清单是**全量**的，写目录里存在的每一件 |
| 链接写成 `README.md` 或缺 `./` | 有的解析器/校验器解不到 → `E-NOTE-LINK` | 统一写 `[文件](./文件)` |
| `一句话结论` 写成"本文提出了一种方法" | 没信息量，且 `W-NOTE-CONCL` | 写清"改了什么 + 换来什么 + 代价/前提" |
| 把导图与思维导图合并成一条 | 清单与实际文件对不上 | 两件是两种产出（C 与 E），各一行 |
| 在索引里重复正文细节 | 与深读重复，改一处漏一处 | 索引只做导航：每件产出**一句话**说明 |

## 六、校验

```powershell
# 单篇索引（模式 note）
python paper-reading/scripts/check_paper_note.py "paper-notes/<短名>/README.md" --mode note

# 也可以不指定模式：有标记行时会自动判为 note
python paper-reading/scripts/check_paper_note.py "paper-notes/<短名>/README.md" --mode auto
```

正样本应打印 `[PASS ] 11 项检查全部通过`。门禁里的 `evals/note-cases/` 用 12 个 fixture（1 正 + 3 只触发 WARN + 8 各触发一个 ERROR）钉住这套口径，其中"漏登记"与"死链"两条都有独立 fixture。
