# 模式 F 模板：难点与解答（`难点-<短名>.md`）

用途：读者有本领域通用基础、**没有这个小方向的基础**，读这篇论文时会卡在若干处。这份文件把这些**卡点**提前列出来并逐个给出可核查的解答，让读者不必来回翻原文。

它是**独立产出**：不并入 `深读-<短名>.md`，也不并入思维导图；一份文件只讲"难点 + 解答"。

## 硬结构（机械校验会查）

```text
# <论文标题> · 难点与解答

## 一、<难点标题>

- **难点**：<一句话点明卡在哪>
- **为什么难**：<读者缺的是哪一块子领域知识 / 哪一步推理断了>
- **常见误解**：❌ <常见错法> → ✅ <正解>
- **解答**：<带来源标记的讲解，≥120 中文字>
- **自检**：<一个能自测是否真懂的问题>

## 二、……
（至少 3 条）
```

- 唯一 `#` 标题，标题必须含论文标题。
- **至少 3 条难点**，小节数不足校验直接报错。
- 每个小节**必须有** `**难点**` 与 `**解答**` 两个字段；缺任一个即报错。
- 每个小节的 `**解答**` 里**必须至少有一处来源标记**：`[原文 p.N]` / `[代码]` / `[摘要]` / `[二手]` / `[OCR]` / `[推断]` / `[数字]`。没有来源的"解答"就是自造知识。
- 小节标题不得重复。
- `**常见误解**`、`**自检**` 缺失 → WARN；`**解答**` 少于 80 字 → WARN（防敷衍）。

## 难点从哪来（不要凭空造）

按这五类去挖，每类至少过一遍：

| 来源 | 怎么找 | 例 |
|------|--------|-----|
| 式子里的写法 | 论文写了但没解释含义的符号/下标/归一化 | "为什么这一步要除以 L1 范数而不是 L2？" |
| 与相邻方法的差别 | 读者容易把本文方法等同于某个熟悉方法 | "LAG 和 FIA 的重要度估计差在哪？" |
| 反直觉的结论 | 结果与常识相反，结论容易被记反 | "为什么中间层的攻击效果反而最好？" |
| 论文表述与实现的缝隙 | 代码/附录与正文不一致 | "论文写乘范数，代码是 L2 归一化后相加" |
| 数字与指标的读法 | 基线口径、设定差异导致误读 | "88.5%→94.1% 与二手转述 89.6%→95.1% 冲突，怎么读" |

**每条难点都必须来自材料**（原文、代码、摘要、二手），不得用领域常识编造"读者大概会问"的问题；编出来的难点会把读者带偏。

## 字段写法

- **难点**：一句话，用读者会问出口的语气（"为什么要跨层递归，不直接把多层梯度加起来？"）。
- **为什么难**：点明缺的是哪块知识或哪一步推理，不要写"这个比较抽象"这类空话。
- **常见误解**：必须是**真实容易发生的**错法，写成 `❌ 错法 → ✅ 正解`。没有把握就不写这个字段（缺了只是 WARN，编造误解比缺字段更糟）。
- **解答**：先给结论，再给理由，最后给证据来源。术语首现照旧要解释。≥120 字。
- **自检**：一个能暴露是否真懂的问题，最好带可对照的答案要点（不要求写完整答案）。

## 文风

- 直接讲，不寒暄、不自述、不写"很多读者可能会疑惑"这类铺垫。
- 每条难点独立可读：不要求读者先读完整篇《深读》。
- 跨文件引用写文件名（"详见 `深读-<短名>.md` 三、方法详解"）。
