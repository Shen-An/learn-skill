# 公式与 Markdown 写法规范

目标：产出在 **Obsidian / GitHub / VS Code 预览 / Typora** 里都能直接渲染，且是**可继续编辑的 Markdown 数学**，不是图片、不是截图、不是纯文本近似。

## 定界符

- **行内公式**：`$...$`，例如 `$\lambda$`、`$\varepsilon=16$`、`$F_i(x)$`
- **行间公式**：`$$` **独占一行**的三行块：

```text
$$
\Delta_i = \nabla_{F_i} J(x) + \lambda \lVert \nabla_{F_i} EA_{i-1} \rVert_2 \nabla_{F_i} EA_{i-1}
$$
```

禁止写法：

- ❌ `$$ E = mc^2 $$`（`$$` 与公式同行）——部分渲染器不认，机械校验会报 `E-DEEP-MATH-LINE`
- ❌ 用代码块装公式（```latex 或 ```math）——会变成不可渲染的源码块
- ❌ 公式截图、公式图片
- ❌ 纯文本近似（`Delta_i = ∇J(x) + λ...`）——不可复现、不可校验
- ❌ 把公式塞进表格单元格做长表达式（表格只放 `$\lambda$` 这类短符号）

## 记法约定（跨渲染器兼容优先）

| 需求 | 推荐 | 避免 |
|------|------|------|
| 范数 | `\lVert x \rVert_2` | `\|x\|`、`\big\| x \big\|` |
| 自适应括号 | `\left( ... \right)`、`\left\{ ... \right\}` | `\big(`、`\Big\{` |
| 算子名 | `\operatorname{Clip}`、`\operatorname{sign}` | `\mathrm{Clip}`、直接写 Clip |
| 分段函数 | `\begin{cases} ... \end{cases}` | 用文字描述分支 |
| 上下标多字母 | `x^{adv}`、`F_{i}` | `x^adv`（会渲染成 $x^a dv$） |
| 空格 | `\,`、`\quad`、`\qquad` | 连续空格 |
| 中文出现在公式内 | 尽量避免；必须时用 `\text{中文}` | 直接混排中文 |

转义竖线：表格单元格里写范数用 `\lVert ... \rVert`，**不要**用 `\|`——`|` 会被 Markdown 表格解析当作列分隔符。行间公式块内可以用 `\|`，但推荐统一改成 `\lVert`。

## 公式的必备配套

1. **符号首现即释**：公式出现过的每个符号，都要在公式后紧接"其中：……"逐项说明，并收进「符号与记号表」。
2. **一句直觉**：每个公式后面补一句"这一步在直觉上等价于什么"。
3. **变量含义唯一**：同一符号在不同节含义不同时，必须在符号表里分别列出并注明适用小节。
4. **公式编号（可选）**：若要引用公式，用行末 `\tag{1}`，正文写"见式 (1)"；不要用 HTML 锚点。

## 交付前的自检

- `$$` 出现次数为偶数，且每个 `$$` 都独占一行
- 每行行内 `$` 数量为偶数（成对）
- 符号表覆盖正文全部符号
- 在至少一个渲染器（Obsidian / GitHub / VS Code 预览）里肉眼确认过一次渲染结果

机械校验：`python scripts/check_paper_note.py <文件> --mode deep`（`E-DEEP-MATH`、`E-DEEP-MATH-LINE`、`E-DEEP-INLINE`、`W-DEEP-SYM`）。
