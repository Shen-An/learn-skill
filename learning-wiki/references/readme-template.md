# 总览 README 模板

Wiki 文件夹的入口，承担四个职责：因果链地图、章节路由、术语速查、复练方法。

```markdown
# <主题> 学习 Wiki

> 本 Wiki 整理自一次完整的学习对话（材料 + 提问 + 推演）。
> 特色：不按百科条目组织，而是按**因果链**组织——每一篇都由上一篇遗留的"不行"逼出来。
> 每一节标题尽量还原为当时提出的真实问题，便于复练。
> 每篇含流程图（Mermaid，GitHub / Obsidian / VS Code 预览可渲染）；文末自测题附**参考答案**。

## 学习主线（一图流）

<ASCII 或 mermaid 的因果链图：每一步 = "上一步的局限 → 引入的机制"，
 例：
 1. <需求A> → <机制A>
 2. <机制A 的局限> → <机制B>
 3. ...>

## 目录

| 文件 | 主题 | 对应主线 |
|---|---|---|
| [01-....md](./01-....md) | <一句话内容> | <链条步骤> |
| ... | | |

## 贯穿全文的思维工具（2~4 条，从本次对话中提炼）

1. **因果链法**：<本主题的"没有功能只有妥协"总述>
2. **概念对暗号**：跨章节互为镜像的机制（如 SDOWN↔PFAIL），帮记忆挂钩
3. **取舍显式化**：凡机制必付账，列举本主题最常见的 3~4 个代价

## 术语速查

| 术语 | 一句话解释 | 详见 |
|---|---|---|
| <术语> | <大白话，与正文首现解释一致或更短> | 0X |

## 复习建议

- 顺序：01→0N；能默画因果链图即整套内化
- 每章自测题先答后校对（答案在文末）
- 增量：新开对话学到新内容时，用本 skill 的增量模式续写，别推倒重来
```

## 一图流的画法

优先 ASCII（任何环境可读），链条复杂再补 mermaid：

```
1. <原始需求/痛点>       → <机制一>（解决 X，留下局限 a）
2. <局限 a>              → <机制二>（解决 Y，留下局限 b）
3. <局限 b>              → <机制三> ...
```

判断标准：只看这一节的人，应能复述"为什么要学下一章"。
