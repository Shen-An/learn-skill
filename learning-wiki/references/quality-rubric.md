# 质量检查清单

先跑 `python scripts/check_wiki.py <wiki目录>` 做机械校验（E1–E5：README 存在/全文件链接可达/编号/围栏；W1–W3：必备小节/README 板块/`见 NN §小节` 悬空引用），
本清单负责机器查不了的部分：逐条人工核对，任何一条不过就返工。

## 结构

- [ ] README 因果链完整：从"最初的问题"到最后一个机制，中间无跳步
- [ ] 每章开头有"因果链定位"，读者知道为什么该学这章
- [ ] 每章有"边界与代价"，说明该机制不行在哪
- [ ] 章节末链接/编号与 README 目录一致（可达性已由脚本 E2/E3/E5 查；这里核对措辞与顺序是否统一）

## 忠实性（最重要）

- [ ] 所有技术论断都来自对话；对话没说的内容要么不写，要么显式标注"本篇未涉及/超出范围"
- [ ] 误解纠正轨迹保留 ❌→✅ 对照，没有被顺滑成"一开始就正确的表述"
- [ ] 学习者的真实提问至少出现在对应章节的标题或引言里
- [ ] 对话中最好的例子/类比没有被替换成更"标准"的讲法

## 术语

- [ ] 每个术语首现有大白话解释；行话堆砌不超过一句就自拆
- [ ] README 术语速查表收录了全部关键术语，且与正文解释不矛盾
- [ ] 无悬空引用：`见 NN-章名 §小节关键词` 式已由脚本 W3 查（引用关键词要能对上真实小节标题的字样）；散文式引用（"前面主从那一节"）仍人工核对

## 图表

- [ ] 每个正文篇 ≥1 张 Mermaid 图；图表达的是决策路径/时序/全景，不是装饰
- [ ] Mermaid 可在 GitHub/Obsidian/VS Code 渲染：含特殊字符的标签已加引号，无裸 `<` `%`
  导致的解析错误；不确定的语句改写成 ASCII 兜底
- [ ] 对比性内容（多方案/多层级）用了表格而非长句

## 自测题与答案

- [ ] 题目考推演不考背诵（"为什么 X 不行""用 A 例子解释 B"），每章 3~5 题
- [ ] 答案写完整推理链，禁止"名词解释 + 就这样"式回答
- [ ] 每章有"一句话总结"，且该句独立成立（脱离上下文能看懂）

## 增量模式附加项

- [ ] 保留了原有章节编号与内容，未无谓重写
- [ ] 被本次对话推翻的旧表述已更新，且新内容里保留 ❌→✅ 记录
- [ ] README 目录、因果链图、术语表已同步延长

## 迭代备忘

任何一条人工项在 ledger（`feedback/ledger.jsonl`）里出现 ≥2 次同类返工，就按 `self-iteration.md` 评估：能机械化的移进 check_wiki.py 并同步加 evals 断言，不能的改写规则或模板——清单只准变短或变准，不准沉积。
