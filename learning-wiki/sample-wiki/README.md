# Redis 主从复制与高可用 学习 Wiki（示例）

> 本 Wiki 整理自一次学习对话（材料 + 提问 + 推演），是 learning-wiki skill 的**示例产出**。
> 特色：不按词条组织，而按**因果链**组织——每一篇都由上一篇遗留的"不行"逼出来。

## 学习主线（一图流）

```
1. 单机 Redis 读负载扛不住     → 主从复制（读写分离、热备；留下异步复制延迟与"没人接管"）
2. 主库挂了没人顶、脑裂不敢切   → 哨兵（自动发现+故障转移；留下单点容量上限）
3. 单机内存与写负载到头         → Cluster 分片（横向扩展+槽路由；留下重分布与多 key 原子性代价）
```

## 贯穿全文的思维工具

1. **因果链法**：没有功能只有妥协——每个机制都为上一步的局限而来，同时欠下新账
2. **概念对暗号**：哨兵的 SDOWN ↔ Cluster 的 PFAIL 互为镜像（主观下线都要升格为客观下线）
3. **取舍显式化**：复制带宽、切换期间的拒绝写、分片后的跨槽操作，凡机制必付账

| 术语 | 一句话解释 | 详见 |
